Generated from the CLI command definitions. Version 0.1.0 is published. Requires Node 20.19 or newer.

## batch plan &lt;repositories.json&gt; &lt;plan.json&gt; | batch submit &lt;plan.json&gt; | batch status &lt;plan.json&gt; | batch dry-run &lt;plan.json&gt;

Plan up to 500 explicit repositories without scanning; submit sequentially with saved retry keys, refresh job/report status, or verify live authorization and allowance without submitting. Keep the same plan when resuming. Exit 0 is not a clean verdict.



## repo &lt;GitHub URL&gt;

Queue a managed repository scan using SHIPTESTED_API_ORIGIN and SHIPTESTED_API_TOKEN. Returns a job ID; exit 0 means accepted, not security checks passed.

- `--private`
- `--request-key UUID (reuse when retrying the same submission)`

## job &lt;id&gt;

Read a managed scan job and its private report URL.



## report &lt;id&gt;

Read an owned saved report from the configured service.



## usage

Read your managed workspace scan allowance.



## scan [path]

Scan a lockfile (default package-lock.json). Only supplied text and exact dependency advisories are checked.

- `--json`
- `--sarif <file>`
- `--fail-on <high|medium|low|any>`
- `--ai`
- `--quiet`
- `--no-color`

## explain &lt;advisory-id&gt;

Read the original untrusted OSV advisory, retrieval date and published fixes.



## mcp

Start the separately installed ShipTested stdio MCP server.



## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Checks passed |
| 1 | Blocked or fail-on threshold reached |
| 2 | Review required |
| 3 | Incomplete |
| 64 | Usage error |
| 70 | Internal error |

Incomplete coverage takes precedence over finding thresholds. SARIF output refuses to overwrite an existing file. Stage events go to stderr; JSON goes to stdout. No ANSI colour is emitted, so NO_COLOR and --no-color are always respected.

## GitHub Actions

Pin the reviewed published package version in your workflow.

```yaml
permissions:
  contents: read
  security-events: write
steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-node@v4
    with:
      node-version: 22
  - run: npx --yes @heysalad/shiptested-cli@0.1.0 scan package-lock.json --sarif shiptested.sarif
  - uses: github/codeql-action/upload-sarif@v3
    if: always() && hashFiles('shiptested.sarif') != ''
    with:
      sarif_file: shiptested.sarif
```

Run this workflow in the repository whose package-lock.json you intend to check. GitHub code scanning availability depends on the repository and plan.
